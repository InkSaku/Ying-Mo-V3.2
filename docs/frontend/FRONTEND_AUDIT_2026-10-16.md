# Ying-Mo 前端审计：减少 AI 生成感

日期：2026-10-16。阶段：只审计，不实施。

Method: dual-agent (A: /root/design_review · B: /root/evidence_review)。A 为独立设计审查，B 为机械扫描与浏览器证据；A 完成前主审未接收 detector 输出。

目标：保留暖纸、宋体、靛蓝批注、手绘线稿及朋友记录空间的气质；让功能文字准确、简短、自然，让页面按阅读、查找、写作和管理任务形成差异。

## 1. 范围与证据

- 以 `frontend/src/App.jsx` 为路由依据，覆盖 47 个页面模块、53 个路由模式（包含通配 404、复用页面的文章/随记及分类/标签分支）。同时检查导航、快速随记、发布确认、评论、共同回忆、媒体、认证布局、状态反馈及样式。
- 已读仓库 `skills/yingmo-handdrawn-ui/SKILL.md`、`docs/product.md`、`docs/frontend/DESIGN.md`，结合 Impeccable critique、clarify、distill。项目的现行设计规范存在于 `docs/frontend/DESIGN.md`，不能因 context 工具未自动找到它而把项目视为新设计。
- 设计判断与机械检查分别由独立代理完成；主审交叉核对源代码、条件分支和产品事实。
- 公共页面有浏览器证据；成员页和后台以源码为依据。没有既有登录态，未为审计注册账号、建立测试数据库或写入业务数据。不能把后者称为全路由运行时验收。
- 本机未找到 humanizer-zh 技能文件；仅采用用户要求的自然中文原则，不声称运行了该技能。产品微文案准确性优先于文学润色。
- 本报告只涉及系统界面和系统兜底文案；成员自己写的标题、简介、正文、合集说明和消息模板不在改写范围。

## 2. 总体判断与优先级

现有视觉已有辨识度。暖纸、宋体、墨色按钮、原色内容影像和情境线稿值得保留。最明显的生成感来自表达密度和结构重复：许多页面同时出现英文眉题、双句文艺标题、释义段、手写旁注、编号和再次解释功能的区块标题。每处单看温和，连续使用后，界面像在不断介绍自己。

不建议换配色、换字体、删除全部插画或把所有页面改成同一种后台布局。

| 优先级 | 问题 | 原因与处理 |
|---|---|---|
| P1 | 阅读范围和通知选项表达不准确 | 写作页的合集可见性仍显示“仅自己”；通知“静音共同投稿”实际也屏蔽评论等非治理通知。先保证文字与现有行为一致。 |
| P1 | 动作和对象需要用户翻译 | “回到我的一页”“拿着邀请码，推门进来”“放进哪一册”及中英混用增加猜测。按钮用动作，对象用一致名称。 |
| P2 | 诗意表达跨页面重复 | “一页、这一册、慢慢、重逢、留下、共同书写”反复解释同一品牌气质。保留少数品牌句，工作页直接进入任务。 |
| P2 | 重复眉题、编号和标题 | `SEARCH / DISCOVERY`、`LIBRARY / 01` 等与中文标题和分页重复。删除无任务意义的层级；真实日期、版本、步骤、顺序与后台 ID 保留。 |
| P2 | 装饰和小字抢占功能空间 | 个人中心六幅场景图、发布框两幅图、欢迎页材质叠加；9–11px 有用信息又过弱。保留主场景，降低重复装饰，提高必要小字可读性。 |

本次没有认定 P0；“P1”表示应在第二阶段优先处理，不等于已证实权限逻辑有漏洞。

### 品牌语言与术语边界

推荐保留欢迎页主句“把今天，轻轻放进时间里。”与全站页脚“写字，也和朋友一起记录生活。”。“漫游”“往年今日”“共同回忆”已经对应具体功能，也可以保留。登录的“好久不见。”可保留为一句问候，按钮仍应叫“登录”。

| 概念 | 面向用户的统一名称 | 边界 |
|---|---|---|
| Article / Note / Post | 文章 / 随记 / 内容 | 需要强调生活记录时可用“记录”；不要为同一控件轮换文学近义词。 |
| Collection | 合集 | “册”可作为数量单位或书册视觉隐喻；导航、表单、错误与确认保持“合集”。 |
| Category / Tag | 分类 / 标签 | 分类页不再另称“栏目”，标签页不再另称“主题”。用户自建标签名不改。 |
| visibility / ACL | 谁可以阅读 / 阅读范围 | 正文解释为“仅自己”“所有映墨成员”“仅合集成员”，不暴露字段或权限算法。 |
| Slug | 网址标识 | 字段旁保留格式示例、锁定条件与真实网址；后台可保留括注 Slug。 |
| ALT | 图片描述 | 首次可用“图片描述（供读屏使用）”；不要与可见图注混为一项。 |
| 登录会话 | 登录设备（页面）/ 会话（必要详情） | 不改真实会话记录、到期时间或撤销范围。 |

### 有限设计评分与使用者影响

评分仅作此次源码审查基线，不代表全站运行时或无障碍验收。

| Nielsen 项目 | 分数（满分4） | 依据 |
|---|---:|---|

| 与真实世界匹配 | 2 | 朋友记录语境明确，普通界面却混入模型名与权限术语。 |

| 错误预防 | 3 | 私密默认与确认流程存在，范围的可见表达仍需先修。 |

| 灵活性与效率 | 3 | 有搜索/保存快捷键、自动保存、筛选和批量能力。 |
| 美学与最小化 | 1 | 重复序言、眉题、编号和说明与真实内容竞争。 |
| 错误识别与恢复 | 3 | 能保留草稿并重试，部分说明仍偏实现语言。 |
| 帮助与文档 | 2 | 行内说明充分，但机制介绍多于简短任务帮助。 |
| 合计 | **24 / 40** | 独立 A 审查基线，后续同范围复审才适合比较。 |

- 初来者：可能把登录“名字”理解为昵称；从分类进入“栏目”、从标签进入“主题”时需要重新识别。
- 经常记录者：六个个人入口各有诗意标题、说明与插图；每次查找草稿或收藏都承受相同阅读成本。
- 关心隐私的作者：发布前最需要确认谁能阅读，目前却先看见“轻轻放好”、选合集和标签的解释。
- 键盘或放大使用者：公共登录流程部分焦点已实测有效；编辑器的最终焦点覆盖、10–11px功能小字与缩放仍需定向验证。

超过四项不自动等于缺陷：个人入口六项、后台导航十二项是实际目的地，应以明确名称和视觉分组降低负担，不能借 distill 删除功能或新加“更多”步骤。
