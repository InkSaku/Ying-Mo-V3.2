# 扫码确认后连接中断：2026-10-14 排查

## 线上证据与结论

用户提供的最近 8 条脱敏会话记录包含 5 条 `blocked`、2 条 `expired`、1 条 `succeeded`。其中失败记录最后保存的扫码响应为 `error_code=0`、`status=new/scanned`，Cookie 名单没有 `sessionid`。这些是旧代码每 4 秒采样的最后快照，不等于触发终止的那次响应；不能把它们解释为“返回 0 却被判成安全验证”，也不能由此断言短信验证已出现。

现有代码在 `check_qrconnect` 返回整数 `2046` 时立即关闭浏览器。官方 SDK 收到这一返回码后仍会处理后续验证。它支持多种方式，包含 `mobile_sms_verify` 和 `push_verify`，不能从这个码单独推断“手机必须收到短信”。对登录凭证稍后写入、设备确认后继续登录的情况，应用会提前结束；旧二维码的迟到响应也没有排除。

## 修正范围

- 收到 `2046` 或扫码 `confirmed` 后进入等待网页登录完成的状态，保留官方页面继续处理；必须拿到并通过严格校验的登录 Cookie，才产生候选登录态。
- 只有官方页面的明确可见验证提示才进入 `blocked`；未产生凭证则报告登录交接未完成，不把协议返回码直接等同于可见短信验证。
- 记录明确的短信或设备确认枚举，并给出相应提示；未知方式保持通用说明。
- 按本次签发的二维码 token 排除旧二维码轮询结果；token 仅在内存比较，不写入诊断。
- 响应变化和成功获取凭证时即时记录结构化诊断，保留成功诊断供失败对照。只保存 Cookie 名称、状态、枚举、字段存在标志，不保存 Cookie 值、票据、手机号或带查询参数的地址。
- 浏览器观察默认 170 秒，给 180 秒会话租约留出保存具体结果的时间。
- 页面优先展示本次连接的具体原因，不再用固定标题覆盖或重复失败原因。

## 验证与上线边界

真实 Chromium 离线夹具覆盖：2046 后延迟 Cookie 成功、无凭证不误报成功/短信、可见验证仍停止、旧二维码响应不影响当前二维码，以及诊断不泄露验证票据。会话测试覆盖设备确认提示及成功诊断保留。前端浏览器测试覆盖具体失败原因的展示。
