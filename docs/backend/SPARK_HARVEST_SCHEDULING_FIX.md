# 每周采集导致每日计划被误关闭

## 定位依据

生产队列显示，2026-10-19 北京时间 03:00 的四个每周采集均为 succeeded。采集当天没有对应的每日自动发送任务；随后两位成员重新模拟检查并开启计划后恢复，另两份未改动的计划一直关闭。账号没有失效，也没有遇到平台验证。

`merge_creator` 给已有私信联系人补入 `short_id`、`user_id` 以及显式 `ambiguous=False`，而原检查指纹包含这些字段（原先为空）。`schedule_due` 因指纹变化判定检查无效，关闭 `auto_run_enabled` 并清空每日到期时间。原私信通道按已有会话名称定位，不依赖此次补入的 creator 资料，因此这次变化没有改变已检查的发送行为。

修复前，隔离测试可以复现：采集成功后 `validation_ready` 立刻变成 false。

## 修复

- 保留已存检查指纹格式，兼容现有检查结果；另外比较采集前后的实际发送行为。
- 仅当原检查有效、已选对象、顺序、凭证、消息、通道和安全标记全部不变时，更新检查指纹以吸收无关资料，不改变原检查时间。
- creator 通道的身份和定位昵称、同名冲突、同步缺失、通道变化仍使检查失效。没有原成功检查、用户修改计划或换号时，不授予检查资格。
- 浏览器读取完成后结束旧数据库快照，按账号、任务顺序加锁，重新读取最新配置与取消状态，防止覆盖期间的成员操作。
- 同步或采集成功只恢复缺失的日程，保留既有到期时间，避免长采集跨过发送时间后把当天任务推到次日。

## 已被误关计划的恢复

管理员命令默认只读：

```bash
APP_ENV=production .venv/bin/python -m flask --app run.py spark-repair-harvest-pauses
# 先完成并验证私有备份，核对预览后：
APP_ENV=production .venv/bin/python -m flask --app run.py spark-repair-harvest-pauses --apply
```

恢复同时要求：当前登录有效、原完整成功模拟检查存在、原指纹只差首次采集新增的三个字段、全部所选对象仍为无冲突的已有私信、计划保存时间早于检查、成功采集后一分钟内发生暂停，以及当前凭证和计划代次能匹配此前自动发送任务的幂等键。主动暂停或修改计划会增加计划代次，因此不匹配恢复条件。

恢复仅更新可证明误关的计划及其未来到期时间。不创建发送任务，不启动浏览器，不改投递去重记录，不补发已经跨日的消息；重复执行无额外修改。

## 回归范围

`backend/tests/test_spark_harvest_schedule.py` 覆盖周一采集到当天自动发送的完整链、跨时点采集、无关元数据更新、真实身份/通道/缺失变化、采集中暂停/换号、只读恢复预览、幂等恢复，以及拒绝恢复主动暂停、消息修改、换号、选人变化、身份风险、失败检查、封禁与缺乏历史计划证据的账号。测试全部使用隔离数据库和离线 driver，没有向真实联系人发送消息。

本次本地验证：新增 25 项故障链与恢复回归通过；后端全量 309 项通过，2 项需要显式隔离 MySQL 库的并发测试跳过；续火花相关 149 项通过；后端源码清单、静态检查和编译检查通过。
