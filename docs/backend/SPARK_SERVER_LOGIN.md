# 服务器扫码后的网页验证

## 问题与行为

本地开发原先使用可见 Chromium，用户可以直接完成官方窗口的后续操作。服务器运行无界面 Chromium，旧代码只转发最初的二维码，后续只显示等待文字；用户无法操作同一次登录里的官方页面。另开用户电脑上的 douyin.com 不会自动把登录凭证交回服务器。

本次在无界面连接收到后续登录响应或发现可见验证后，显示“继续完成登录”。页面展示该会话当前的官方登录画面，会员可以点击、拖动、滚动，按实际提示扫描后续二维码，或向已选输入框填入数字。官方流程完成后关闭预览，进入账号确认，确认后才绑定并同步联系人。可见浏览器的本地连接继续使用原窗口。

预览每约 1.5 秒刷新，图片可放大查看。操作有延迟，上一步更新后再继续。验证码或手机号需先点击官方画面中的对应输入框，再点击“填入已选输入框”。没有把协议中的可选验证方式写成“必须短信验证”。

## 部署

本次包含前端、后端、后台进程和数据库迁移 `20261014_0016`，需要一起更新。仅替换前端或重启网站进程不能完成更新。

把本次代码发布到服务器使用的分支后，按现有流程运行：

```bash
cd /var/www/yingmo
bash deploy/deploy.sh
```

脚本会停止 `yingmo-spark`、更新代码、执行 `flask --app run.py db upgrade`、重启 `yingmo` 与 `yingmo-spark` 并构建前端。服务器沿用 `APP_ENV=production`；`SPARK_LOGIN_HEADLESS` 默认为 true，如果曾手动设为 false，应改回 true。无需额外安装桌面或暴露浏览器调试端口。保留原 `SPARK_CREDENTIAL_KEY`。

更新后检查：

```bash
cd /var/www/yingmo/backend
.venv/bin/python -m flask --app run.py db current
systemctl is-active yingmo yingmo-spark
```

迁移版本应为 `20261014_0016`，两个服务均为 active。刷新网站，取消旧连接后重新扫码；只有新会话才能使用新后台流程。

## 交互与数据边界

- 预览和输入必须携带当前会员的登录鉴权，检查会话所有者、有效期、账号版本与状态；图片不进入公开媒体库、浏览器缓存或 Service Worker 缓存。
- 图片与待处理数字输入使用现有凭证密钥加密保存。完成、取消、过期、解绑或后台恢复中断会话时清除。
- 操作限定为画面范围内的点击、拖动、有限滚动、数字输入及少量按键。不接受任意脚本、网址或浏览器快捷键；文本不会填入聊天编辑器。
- 页面版本、递增序号和单个待处理操作防止陈旧或重复请求再次执行。用户操作完成验证，后台不自动识别或破解验证码。
- 登录观察约 5 分钟，数据库租约 310 秒，进程上限 320 秒；后续排队任务不会无限等待。
- 当前不转发本机摄像头、麦克风等设备能力。如果官方流程必须调用这些能力，仍需使用备用本机扫码脚本。此次不声称所有平台验证分支均已实测。

## 验收与限制

真实无界面 Chromium 配合离线官方流程夹具验证了：后续页面截图、用户点击继续、凭证生成后自动接回，以及禁止向聊天编辑器输入数字。接口验证了会员隔离、加密、不缓存、过期、重复输入、取消与成功清理；浏览器测试验证页面点击坐标、数字输入、操作序号、账号确认与移动端布局。另执行数据库升级/回退与 MySQL DDL 检查。
