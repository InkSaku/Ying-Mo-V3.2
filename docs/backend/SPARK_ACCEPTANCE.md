| 好友台账、勾选顺序、手动添加 | 用户所属 `spark_contacts`，持久化选择、顺序和资料 |
| 台账统计、火花排行、近期发送 | 概览的 `ledger_stats` 与“好友台账概览” |
| 待发送名单与首条消息日计数 | `pending_send`、`creator_sent_today`，发送确认中显示预计名单 |
| 消息模板、时间、间隔、浮动、人数上限 | 原生 React 表单、严格类型和范围验证；单轮最多 500 位 |
| 每日执行、自动运行开关 | 北京时间计划、持久化队列、每日唯一调度键 |
| 模拟运行、立即续火花 | `dry_run` / `send`；模拟不写发送记录，不创建真实补发 |
| 失败 45 分钟补发 | 只补发送前确认失败的好友，每账号每日最多一批；不补未知结果 |
| 双通道、每日首条消息限制 | 默认关闭 creator 首条消息，每轮最多一位；计数包含成功、已尝试和待确认 |

| 原运行状态、日志 | 用户所属批次与逐好友结构化事件，不保存 Cookie、签名 URL 或消息正文 |

网站入口为 `/tools/spark`，个人空间按钮和个人导航“工具”组均可进入。所有接口要求有效成员；普通成员无法读取、编辑、取消或执行他人的资源。

## 执行与恢复语义

- 一个独立后台串行执行数据库任务。任务执行子进程继承单实例文件锁，不允许第二个后台同时启动。
- Chromium 使用新的上下文，在内存加载所属用户的登录态；不保存网页截图、原始接口 URL 或明文凭证。
- 精确匹配会话标题，拒绝可见同名联系人；creator 通道确认聊天区域标题后才输入。
- Enter 前持久化发送意图，按用户、日期、好友防重。成功或未知结果不会再发，按 Enter 后出现验证也保留发送结果为未知。
- 更新凭证使旧版本任务失效。相同账号身份能确认时保留选择；否则清空旧好友，防止账号切换后误用名单。
- 解绑取消该用户全部任务并删除登录态与好友，历史结构化执行记录保留。已进入发送阶段的消息不能撤回。
- 停用或封禁的映墨账号不执行任务。平台登录失效或验证提示暂停该抖音账号的计划，重新导入或同步成功后可恢复。
- 配置、日程、排队任务、结果保存在数据库。服务重启不重放中断的发送；已写入 Enter 意图的中断记录标为待确认。
- 不补发过期日期的每日消息。单个任务默认最多 1200 秒，systemd 示例限制整个后台及子进程为 1800 MB。
- 此实现以单台服务器、一个后台为部署边界；多主机需要数据库级分布式执行租约，第一阶段不承诺这一部署形式。

## 外部环境尚待验收

没有用户真实登录态和生产服务器访问，本次无法验证抖音当前网页结构、真实会话恢复、真实好友发送、异地登录提示或连续每日运行。源码包含真实 Playwright 适配器，但离线通过不能替代这些验证。
